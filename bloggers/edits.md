1. Интеграции — выбор контрагента
Задача:
При выборе контрагента в интеграциях сделать так, чтобы новый созданный контрагент отображался в начале списка.
Логика:
После создания нового контрагента он должен быть первым в списке выбора.
Не нужно заставлять пользователя искать его вручную в общем списке.
2. Доставка — фильтр по сотруднику
Задача:
В разделе доставки добавить фильтр по сотруднику.
Логика:
Должен быть фильтр / селект по сотрудникам.
При выборе сотрудника показывать только доставки, закреплённые за ним.
Фильтр нужен для быстрого просмотра доставок конкретного менеджера.
3. Учётка менеджера — видимость трек-номеров
Задача:
Сделать разграничение доступа по трек-номерам в учётке менеджера.
Логика:
Менеджер должен видеть только свои трек-номера.
Треки других менеджеров не должны отображаться.
Это должно работать в разделе доставки / заказов / задач, где используются трек-номера.
4. Учётка менеджера — задачи только своего сотрудника
Задача:
Сделать так, чтобы задачи падали только на учётку нужного менеджера.
Логика:
Если задача закреплена за конкретным сотрудником, она должна быть видна только ему.
Другим менеджерам эта задача мешать не должна.
В общей админке задачи могут оставаться видимыми, если есть права администратора.
5. Интеграции — добавление позиции
Задача:
В раздел интеграций добавить возможность создавать дополнительные позиции.
Что должна содержать позиция:
Название / заголовок
Статус
Соцсеть
Контрагент
Условия сотрудничества
Ответственный сотрудник
Дата
Логика:
Можно добавить несколько позиций.
Каждая позиция должна отображаться в общей таблице.
По этим позициям в дальнейшем должен считаться бюджет.
6. Интеграции — расчёт бюджета
Задача:
Добавить расчёт бюджета по созданным позициям.
Логика:
У каждой позиции должна быть сумма / бюджет.
В общем списке должна отображаться общая сумма бюджета.
Если добавлено несколько позиций, бюджет должен суммироваться.
Нужно визуально понимать общую картину по интеграциям.
7. Интеграции — новый статус
Задача:
Добавить новый статус для интеграций:
Не отвечает
Логика:
Статус должен быть доступен в выпадающем списке.
Использовать его для контрагентов, которые перестали отвечать.
8. Создание интеграции — выбор сотрудника до сохранения
Проблема:
Сейчас сотрудника нельзя выбрать сразу, он появляется только после сохранения.
Задача:
Сделать выбор сотрудника сразу при создании интеграции.
Логика:
В форме создания интеграции должен быть селект сотрудника.
Можно выбрать ответственного сотрудника до сохранения.
Если сотрудник не выбран вручную, можно автоматически ставить текущего пользователя.
9. Интеграции — фильтр по месяцу
Задача:
Добавить фильтр по месяцу.
Логика:
Фильтр должен позволять выбрать месяц.
После выбора месяца показывать только интеграции за этот месяц.
Дата должна браться из поля даты интеграции / публикации.
10. Визуал — уменьшить шрифт в панели фильтров
Задача:
В панели с фильтрами уменьшить размер шрифта.
Проблема:
Сейчас шрифт слишком большой, визуально выглядит тяжело.
Что сделать:
Уменьшить размер текста в фильтрах.
Сделать фильтры компактнее.
Особенно обратить внимание на блок фильтров сверху таблицы.
